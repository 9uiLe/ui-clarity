# 目的に応じた検証

依頼の範囲と完成条件から確認を選ぶ。毎回すべてを行う一覧ではない。比較不要・操作不要の用途に、試験のための機能を追加しない。

## 先に決める観測

| 用途 | 代表作業 | 成立を示すもの |
| --- | --- | --- |
| 説明・共有 | 元資料を読まずに全体・親子・同列・重要度を説明する | 表示上の根拠と、元資料に沿う答え |
| UIの所属・対象・状態・操作 | 一文へ詰め込まれた表示から所属先、対象、誰の状態か、操作の結果を読み取る | 構造と表示で役割を区別し、状態を子対象にしない。反復説明を増やさず必要情報を保つ |
| ドキュメント | 読者が必要な内容・条件・例外を読み取る | 用語・説明順・まとまりが用途に合い、根拠と意味を保つ |
| コードコメント | コメントを対応するコードと照合する | 条件・前提・意図が一致し、参照情報・処理用指示・実行コードを保つ |
| 比較 | 必須条件に合う候補を探し、有効候補間の違いで判断する | 条件・単位・除外理由・不明点を失わず辿れる |
| 操作 | 現在状態を読み、次へ進み、結果やエラーを確認する | ラベル・実処理・表示状態が一致する |
| AIへの指示 | 画面で理解した対象と変更意図を伝える | 受け手が同名の別対象から元のコード・レコード・項目を特定できる |
| 文言のみ | 編集前後を仕様・差分と照合する | 意味・条件・保護対象と変更範囲が保たれる |
| レビューのみ | 問題を場所・根拠・影響付きで報告する | ファイルに変更がなく、推測と事実を分ける |

AIへの指示の確認では、可能なら画面だけを見る役と元資料で照合する役を分ける。同名対象も含め、利用者が選んだ対象と受け手の特定した対象が一致するか調べる。AIによる代理回答は人の理解を実証しない。

未知値、曖昧な内部名、同名の別対象、長い値、条件・例外、補間変数などは、対象に該当するときに代表入力へ含める。不明点を推測で埋めず保持できるか確認する。

UIの役割を表し分ける確認では、状態の対象が未確認の例や、パスのままで用途を満たす例も使う。単に文を分割した、短くした、バッジやカードを増やしたという理由で合格にしない。文言だけの依頼では構造が保持され、構造上の改善が別提案になっているかを確認する。

## 検査方法と主張の限界

- **静的検査**：差分、保護対象、参照先、構文、意味構造、既存テスト。画面の見え方や実操作の成功の証明にはならない。
- **描画と実操作**：利用できる環境では代表的な幅、文字拡大、長い値、エラー状態を実画面で見る。必要なボタン、キーボード操作、選択と結果、参照情報を実際に試す。対象・条件・観測結果を記す。文字拡大と画面ズームを同じ検査と呼ばない。
- **人による理解**：元資料を読んでいない人に、全体・関係・違い・次の操作などの課題を試してもらう。作成者やAIだけの確認は、その範囲を明記する。
- **実際の読み上げ**：対象環境の支援技術で、名前・説明・関係・読み順・状態変化を確認する。静的検査やツリーの確認で代用したと書かない。

狭い修正は差分と影響する代表箇所を確認する。共有文字列の修正は参照先へ検証範囲を広げる。必要な環境が使えなければ、その条件と未実施項目を示す。

完了報告は、何を作成・変更したか、目的、実施した方法と条件・結果、残る未確認を短く述べる。全体の理解だけ、終了コードだけ、画面が開いたことだけで、必要な比較・操作・特定まで成立したと一般化しない。
