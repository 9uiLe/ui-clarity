# 成果物の日本語と意味の保護

## 共通の基準

成果物の読者・用途、既存の用語集・文体を優先する。同じ概念には同じ語を使い、異なる対象や状態の区別を保つ。必要な説明、条件、例外、根拠を残し、読者が理解できる言い方を選ぶ。会話の返答や進捗報告の文体を、この基準で毎回修正する必要はない。

主語・対象、否定、条件と例外、数値、単位、期間、概数、可能性、断定の強さを保つ。例えば「約5分」「最大5分」「5分以内の場合がある」は同じ意味ではない。誤りが疑われても、根拠なく断定を強めたり仕様を変更したりしない。仕様・実物・記述が矛盾したら、場所と相違、読者への影響を示す。

## ドキュメント

読者が知りたいことに沿って、用語、説明の順序、見出し、段落のまとまりを整える。仕様書・手順書・READMEなどの役割と既存の専門性を保ち、すべてを一般向けの短い説明へ置き換えない。参照先、数値、条件、例外、根拠を元資料と照合する。文言だけの依頼では、見出し構造や表への組み替えは別提案にする。

## コードコメント

対応するコードを読み、対象、条件、前提、意図と記述の一致を確かめる。実装から分からない理由を推測で補わない。コメントの改善依頼では実行コードを変更せず、コードとの不一致があれば報告する。

識別子・パス・URL・数値・補間などの参照を保護する。コメント内のコマンド、サンプル、型・lint・生成ツール向けの指示は役割を確かめ、自然言語の説明と分けて扱う。docstringなど実行時にも参照される文字列は、その用途を確認する。UI向けのボタン、状態表示、アクセシビリティ属性をコメントへ持ち込まない。

## UIの動作と表示を対応させる

用語集、既存の文体、読者、仕様、実装を先に調べる。操作の対象・結果・現在状態・適用条件が確定してから書く。内部名称を直訳して意味が通ると考えない。同じ概念・操作には同じ語を使い、異なる動作は区別する。

| 文言の役割 | 必要な情報 | 避けること |
| --- | --- | --- |
| 見出し | その領域の内容や役割 | 内部名だけ、同じ見出しの乱用 |
| 操作ラベル | 押すと実際に行われる操作と必要な対象 | 確認へ進むだけのボタンを「送信」、実行前を「送信しました」 |
| 状態表示 | 確認できている現在状態 | 試行開始を成功と呼ぶ、未知値を既知状態へ丸める |
| 設定の説明 | 適用対象・条件・効果 | オン／オフで変わる範囲や例外を落とす |
| 操作案内 | 次に必要な行動と条件 | できない操作を案内する、必須と任意を混ぜる |
| エラー | 判明している事象、根拠のある対処 | 原因・保存状況・復旧見込み・再試行の安全性を推測する |

「確認する」「保存する」「送信する」「削除する」等は実際の処理に対応させる。短い名詞ラベルも文脈から操作が分かればよく、すべてを同じ語尾へ変えない。

## UIの文言のみを変更するとき

1. 表示文字列と、支援技術向けの名前・説明の取得元を確認する。子テキスト、関連するラベル、参照先、ネイティブのプロパティなどを調べる。
2. 必要な文言だけ変更する。既存の `aria-label` 等が表示ラベルとずれる場合は文字列の整合を扱うが、新たな属性・関連付けや構造変更が必要なら別提案にする。記号だけの操作に名前がなければ、その不足も報告する。
3. 差分で、識別子、翻訳キー、関連付け、イベント、処理値、URL、書式指定子、補間変数、複数形の分岐構造が保持されていることを確認する。日本語に翻訳しないものまで変更しない。
4. 共有文字列は参照先を調べ、異なる操作で共用されていないか確認する。一方に適した変更が他方の意味を変えるなら、黙って共通文字列を置き換えない。分割が必要で範囲外なら提案する。

`{count}`、`%1$s`、`${name}` などは、その仕組みの補間として扱う。並び替えの可否を実装で確認し、文字列中の処理用トークンや ICU MessageFormat の分岐・キーを文章として編集しない。構文検査だけで意味保持を保証したことにはしない。

## UIの支援技術と表示

文字の表示ラベルがある操作は、その文字をアクセシブルな名前に原則含める。例えば表示「内容を確認する」に対して名前が「送信する」のままでは整合しない。既定の名前で足りる要素に `aria-label` を一律追加しない。説明は名前と役割を分け、関連付けを壊さない。

見出しのレベル、表の見出しとセル、フォームのラベル・説明・エラー、読む順序・フォーカス順序と視覚配置の対応を確認する。Webの属性をネイティブアプリへそのまま持ち込まず、対象環境の意味構造・アクセシビリティAPIで確認する。アクセシビリティツリーの取得は、実際の読み上げ確認とは区別する。
